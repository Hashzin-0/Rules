# Regra 12 — Organização e documentação

Mantenha nomes claros, documentação alinhada ao comportamento real e exemplos executáveis quando possível. Atualize instruções quando arquitetura, APIs, banco, configuração ou fluxo de desenvolvimento mudarem. Prefira atualizar uma fonte existente a criar documentos duplicados.

Documente objetivo, pré-requisitos, configuração, comandos, variáveis necessárias sem valores secretos, exemplos, limitações e troubleshooting. Marque exemplos ilustrativos como exemplos; não os apresente como testes executados.

Use links oficiais para frameworks, SDKs e serviços. Registre a versão/escopo ao explicar comportamento que muda entre versões. Revise links, caminhos e comandos na validação.

Critérios: [ ] documentação atualizada; [ ] exemplos coerentes com código; [ ] segredos omitidos; [ ] comandos e versões identificados; [ ] links revisados.

Referências: https://www.w3.org/guide/github/best-practices.html ; https://keepachangelog.com/en/1.1.0/ ; https://docs.github.com/en/actions/get-started/continuous-integration
